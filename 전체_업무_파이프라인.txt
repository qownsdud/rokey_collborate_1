================================================================================
[전체 업무 파이프라인] AI 기반 키오스크 실물 라인아트 협동로봇 드로잉 시스템
================================================================================

1. 프로젝트 개요 및 목표
--------------------------------------------------------------------------------
- 목적: 그림을 그리기 어려워하는 고객이 키오스크에서 러프 스케치와 키워드 3개만
  입력하면, AI가 깔끔한 흑백 라인아트를 생성하고 두산 협동로봇이 이를 실제 종이
  위에 펜으로 그려주는 무인 자동화 드로잉 시스템 구축.
- 핵심 지표(KPI):
  * 라인아트 변환 시간: 1초 이내 (OpenCV `cv2.Canny` 기준 수십 ms, 추후 AI 옵션 전환 시 3~10초 이내)
  * 이미지 → 벡터 경로 변환 시간: 1초 이내
  * 로봇 1장당 드로잉 시간: A4/엽서 기준 1분 30초 ~ 3분 이내
  * 원가 산정 기준: (1장당 잉크 소모량 + 용지 1장 [+ AI 옵션 시 API 호출 비용]) vs 판매가 비교

2. 전체 시스템 아키텍처 (End-to-End 데이터 흐름)
--------------------------------------------------------------------------------
[고객]
  │ (터치스크린/카메라: 원본 이미지 또는 스케치 입력)
   ▼
[1단계: 키오스크 UI 및 전처리] (`phase1_kiosk/` — FastAPI + 웹캠/업로드 UI)
  │ - 웹캠 촬영 또는 사진 업로드 → 이미지 정규화(`normalize_photo_bytes`)
  │ - 디테일 수준(`high`/`medium`/`low`) 및 용지 규격(`a4`/`postcard`/`square`) 선택
   ▼
[2단계: 라인아트 변환] (`phase2_lib_lineart/` — 로컬 DL `LineartDetector` / OpenCV)
  │ - 키오스크 서버가 `phase2_lib_lineart/main.py` 호출 (`--method dl`, `--binarize`)
  │ - 이진화 및 용지 비율 맞춤 후 사용자 확정 시 `confirmed_outputs/latest_lineart.png` 저장
  │ * (참고: 클라우드 AI `phase2_ai_lineart/` 및 `lineart_onetouch/`는 `X/`로 이동 보관)
   ▼
[3단계: 벡터 경로 추출 및 좌표 변환] (path_planner_node / OpenCV + Python)
  │ - 이진화 → 세선화(1px 중심선) → 경로 단순화(approxPolyDP) → TSP 경로 정렬
  │ - 픽셀 좌표(px, py) → 로봇 작업 좌표(X, Y, Z_draw / Z_up) 변환
   ▼
[4단계: 로봇 드로잉 실행] (robot_drawer_node Action Server + 두산 협동로봇)
  │ - ROS2 Action으로 Stroke 목록 수신, 실시간 진행률(Feedback) UI 전송
  │ - DSL 기반 제어(move_joint, move_task, moveB) + 스프링 탄성 펜 홀더 필압 보정
   ▼
[5단계: 완료 및 안전 복귀]
  - Home Pose 복귀 → 고객 완료 안내 및 그림 수령 → 다음 대기 상태 전환


3. 단계별 상세 업무 파이프라인
--------------------------------------------------------------------------------

[Phase 1] 키오스크 사용자 입력 및 전처리
1) 사용자 입력 수신
   - 캔버스 UI에서 사용자가 손/터치펜으로 그린 러프 스케치 이미지 수신
   - 그림 특징을 설명하는 키워드 3개(텍스트) 입력 수신 (예: "고양이", "우주복", "웃는 모습")
2) 입력 이미지 정규화 (Pillow / OpenCV)
   - 해상도를 512x512 또는 1024x1024 정사각형으로 리사이즈/패딩
   - 투명 배경(RGBA PNG)일 경우 알파 채널을 합성하여 순백색(#FFFFFF) 배경에
     검정색(#000000) 선으로 통일
3) 키워드 검증 및 정제
   - 사전 정의된 금칙어 리스트로 부적절한 키워드 즉시 차단 및 재입력 안내
   - 영문 기반 모델(ControlNet 등) 사용 시 키워드 3개를 영어로 자동 번역/정제

[Phase 2] 라인아트 변환 (현재 우선: OpenCV `cv2.Canny` 엣지 검출 방식)
* GPU·인터넷·외부 API 과금 없이 일반 PC CPU만으로 즉시 동작하도록 비-AI 영상처리
  방식(옵션 C)을 우선 적용함. (추후 키워드 창작 기능 필요 시 `phase2_ai_lineart/`
  클라우드 AI [옵션 A] 또는 로컬 SD+ControlNet [옵션 B]로 확장 가능)
* 구현 위치: `phase2_lib_lineart/lineart_cv.py` (`LineartConverterCV`, `mode="canny"`)
1) 전처리 및 노이즈 억제
   - 입력 이미지를 목표 최대 변 길이(예: 512px) 기준으로 비율 유지 리사이즈
   - 그레이스케일 변환 후 `cv2.bilateralFilter`를 적용해 윤곽선(Edge)은 보존하면서
     질감·잔주름 등 불필요한 고주파 노이즈 제거
2) Canny 엣지 검출 및 흑백 반전
   - `cv2.Canny(smoothed, canny_low, canny_high)`로 단일 픽셀 수준의 엣지 추출
     (기본 임계값: `canny_low=50`, `canny_high=150`, 필요 시 대상별 튜닝)
   - `255 - edges` 반전 적용으로 순백색 배경(255) 위 검정색 선(0) 이미지 생성
3) 출력 규격 맞춤 및 유효성 검증
   - 로봇 드로잉 용지(A4 210x297mm, 엽서 100x148mm, 정사각형) 비율에 맞춰 흰색 패딩
   - [참고] 기존 클라우드 AI 프로토타입(`phase2_ai_lineart/`: Cloudflare Workers AI
     `flux-2-klein-4b`, FastAPI `/generate-lineart`)은 확장 옵션으로 보존

[Phase 3] 벡터 경로 추출 및 로봇 좌표 변환 (path_planner_node)
* 픽셀(래스터) 방식은 Z축 승하강 수만 회 발생으로 시간·번짐·관절 마모 문제가 있으므로
  반드시 연속 선(Stroke) 기반 벡터 경로 방식을 사용함. (처리 시간 1초 이내)
1) OpenCV 4단계 경로 추출
   - (단계 1) 전처리 및 이진화: Otsu/고정 임계값으로 순수 흑(0)/백(255) 변환, 필요 시
     모폴로지 연산(Open/Close)으로 잡티 제거
   - (단계 2) 세선화(Thinning/Skeletonization): cv2.ximgproc.thinning 또는
     skimage.morphology.skeletonize로 두꺼운 선을 1픽셀 중심선으로 추출 (이중선 방지)
     * 외곽선 스타일 필요 시 cv2.findContours 선택 활용
   - (단계 3) 경로 단순화: Douglas-Peucker(cv2.approxPolyDP) 적용으로 직선 구간의
     불필요한 중간점을 제거하여 데이터 크기 80~90% 이상 감소
   - (단계 4) 노이즈 필터링 및 순서 최적화:
     * 길이 5px 미만 또는 점 2개 이하 잡선 제거
     * 공중 이동(Pen-Up) 최소화: 최근접 이웃(Nearest Neighbor) 기반 TSP 휴리스틱 정렬
     * 총 이동 거리/점 개수 임계치 초과 시 approxPolyDP 허용 오차 상향 조정 (시간 준수)
2) 로봇 작업 좌표 캘리브레이션
   - 픽셀 좌표 (px, py) → 종이 작업 영역 로봇 좌표 (X, Y) 선형 매핑
     (예: A4 용지 내 여백 제외 160mm x 160mm 영역 스케일링 및 오프셋 적용)
   - 작업대/종이 기울어짐 보정이 필요한 경우 4점 기준 아핀/호모그래피 변환 적용
   - Z축 높이 정의:
     * Z_draw: 펜촉이 종이에 닿아 그리는 기준 높이
     * Z_up: Stroke 간 이동 시 안전 높이 (Z_draw + 10~20mm)
3) 출력 데이터 포맷 (ROS2 Service/Action 전송용)
   - Stroke 단위 좌표 배열 구성:
     [{"stroke_id": 1, "points": [[x1, y1], [x2, y2], ...]}, ...]

[Phase 4] ROS2 연동 및 두산 협동로봇 드로잉 제어 (robot_drawer_node)
1) ROS2 노드 및 통신 구조
   - kiosk_ui_node: 스케치/키워드 입력, AI 이미지 경로 발행, 진행률/상태 HMI 표시
   - path_planner_node: AI 이미지 구독 → 경로 추출/좌표 변환 → Action Goal 전송
   - robot_drawer_node (Action Server):
     * MoveIt2 또는 두산 로보틱스 ROS2 드라이버 / DART-Platform(DSL) 연동
     * 현재 실행 중인 Stroke 번호(진행률 %)를 Action Feedback으로 실시간 송신
     * 비상 정지(E-Stop), 일시정지, 작업 취소 요청 즉시 처리
2) 두산 협동로봇 동작 시퀀스 및 DSL 명령 매핑
   - 초기 대기 자세(Home Pose) → 작업 영역 상단 이동: move_joint
   - 펜 파지/교체(필요 시): digital_out_2_grasp(잡기), digital_out_1_release(놓기)
   - 각 Stroke 실행 루프:
     1. Stroke 시작점 상공(Z_up)으로 고속 이동: move_task(linear), 200~300 mm/s
     2. 그리기 높이(Z_draw)로 하강: move_task(linear)
     3. points 순차 추종: move_task(linear) 및 moveB(복합 연속 모션/Blending) 적용으로
        꼭짓점 정지 시간 손실 제거 (속도 50~100 mm/s)
     4. 마지막 점에서 Z_up으로 상승: move_task(linear)
   - 모든 Stroke 완료 후 Home Pose 복귀: move_joint
3) 기구부 및 필압 제어 보완
   - 스프링 탄성(Compliance) 펜 홀더(3D 프린팅 + 볼펜 스프링, Z축 3~5mm 유격) 적용으로
     책상/종이 수평 오차(0.5~2mm)를 기구적으로 흡수하여 일정한 필압 유지
   - 필요 시 두산 로봇 내장 기능 보조 활용: compliance(순응제어) 또는 force(힘제어,
     상대모드 ON으로 외력 0 보정 후 설정 힘 유지)
   - 펜 선정: 수성 싸인펜, 붓펜 또는 마커(낮은 마찰력, 번짐 최소화)
   - 종이 고정 지그(Jig): 자석/클립/논슬립 패드로 종이 위치 고정(반복 정밀도 확보)

[Phase 5] 완료 처리, 예외 대응 및 현장 안전 운영
1) 완료 및 고객 응대
   - 로봇이 시야/수령 구역을 가리지 않는 Home Pose로 복귀
   - 키오스크 화면에 완성 안내 및 수령 가이드 표시 후 초기 화면 자동 복귀
2) 예외 상황별 대응 매트릭스
   - 부적절한 키워드 입력 → 금칙어 필터 차단, 수정 요청 팝업
   - AI API 타임아웃/오류 → 1회 자동 재시도 → 재실패 시 오류 안내 및 초기화
   - 생성 이미지 비어 있음/손상 → 유효성 검사 실패 처리 후 재생성 또는 오류 안내
   - 경로 과다(예상 시간 3분 초과) → approxPolyDP 허용 오차 자동 상향 및 재계산
   - 로봇 이상/비상 상황 → E-Stop 즉시 정지, 안전 복구 절차 수행 후 대기 자세 복귀
3) 협동로봇 현장 안전 기준 (협동로봇_주의사항.pdf 준수)
   - 충돌방지 7대 조치 이행:
     1) 비상정지장치(E-Stop) 고객/운영자 접근 가능 위치 설치
     2) 협동운전 모드 적용 (동력 및 힘 제한 / 속도 및 위치 감시 등 최소 1개 이상)
     3) 협동작업 영역 바닥/표지판 표시 및 투명 아크릴 안전 커버/펜스 설치(손 끼임 방지)
     4) 위험성 평가 및 운영자 안전 교육 실시
     5) 보호장치·비상정지 등 안전성능 정기 확인
     6) 유지보수 외 시스템 임의 설정 변경 금지(접근 권한 관리)
     7) 협동작업 영역 내 위험요소 제거 및 정리정돈


4. 통합 검증 및 테스트 체크리스트
--------------------------------------------------------------------------------
[ ] AI 모듈: 다양한 스케치+키워드 10종 이상에 대해 음영 없는 흑백 라인아트 생성 및
    3~10초 이내 응답 확인 (네트워크 차단/금칙어/타임아웃 재시도 테스트 포함)
[ ] 경로 추출 모듈: 1초 이내 세선화·단순화·TSP 정렬 완료 및 예상 시간(3분 이내) 준수 확인
[ ] 좌표 캘리브레이션: A4 지그 네 모서리 및 중심점 기준 정밀도(오차 1mm 이내) 검증
[ ] 로봇 드라이런(Dry-Run): 펜을 장착하지 않고 허공(Z_up 오프셋)에서 전체 궤적/속도 검증
[ ] 실물 드로잉 테스트: 스프링 펜 홀더 장착 후 선 끊김/뭉개짐 없이 1장 완성 확인
[ ] 안전/비상정지 테스트: 드로잉 중 E-Stop 및 UI 취소 버튼 작동 시 즉시 안전 정지 확인


5. 현재 구현 현황 및 보완 필요 사항 (2026-11-13 16:07 기준)
--------------------------------------------------------------------------------
1) 구현 완료 (Phase 1 ~ Phase 2 연동)
   - `phase1_kiosk/`: 웹캠/사진 업로드 키오스크 UI(`static/`) 및 FastAPI 서버(`server.py`),
     입력 정규화(`preprocess.py`) 구현 완료
     * `POST /api/kiosk/photo`: 사진 정규화 → `phase2_lib_lineart` 로컬 DL(`--method dl`)
       선화 변환(`high`/`medium`/`low` 프리셋, 이진화, 용지 비율 패딩)
     * `POST /api/kiosk/confirm`: 확정 이미지를 `confirmed_outputs/latest_lineart.png`로
       저장(이전 파일은 `history/`로 자동 아카이브)
     * `GET /api/kiosk/latest`: 최신 확정 이미지 메타정보 조회
   - `phase2_lib_lineart/`: 로컬 DL(`LineartDetector`) 및 OpenCV(`dodge`/`canny`/`adaptive`)
     선화 변환 CLI 모듈 구현 완료
   - 기존 실험/보류 모듈(`phase2_ai_lineart/`, `lineart_onetouch/`)은 `X/` 폴더로 정리 이동됨
2) 보완 및 연계 확인 필요 사항
   - `phase1_kiosk/server.py`는 현재 `--method dl`을 호출하며, 필요 시 `--method cv --cv-mode canny`
     전환 옵션 추가 가능
   - `phase2_lib_lineart/.venv` 환경 의존성 및 실제 키오스크 구동 시 변환 속도 측정 필요
3) 미착수 영역 (다음 진행 단계)
   - Phase 3: `confirmed_outputs/latest_lineart.png`를 입력으로 받는 벡터 경로 추출
     (세선화·`approxPolyDP`·TSP 정렬) 및 로봇 좌표 변환 (`path_planner_node`)
   - Phase 4: ROS2 Action Server (`robot_drawer_node`) 및 두산 협동로봇 실물 연동
